### q1. Как работает модель word2vec и какие две архитектуры она использует?

**Ожидание:** Названы обе архитектуры — CBOW (предсказание слова по контексту) и skip-gram (предсказание контекста по слову); объяснено, что модель обучает векторные представления слов на основе совместной встречаемости.
**Источники:** word2vec — статья Википедии

**Без RAG (2/2):** Ответ называет обе архитектуры — CBOW (предсказание слова по контексту) и skip-gram (предсказание контекста по слову), и объясняет, что модель обучает векторные представления слов на основе контекстной совместной встречаемости. Фактических ошибок нет.
**С RAG (2/2):** Ответ называет обе архитектуры — CBOW (предсказание центрального слова по контексту) и skip-gram (предсказание контекста по слову), и объясняет, что модель обучает векторные представления слов на основе совместной встречаемости/контекстной близости. Фактических ошибок нет.

Ответ без RAG:

> word2vec — это модель для получения векторных представлений слов (эмбеддингов), обучаемая на больших текстовых корпусах. Идея: слова, встречающиеся в похожих контекстах, получают близкие векторы.

Две архитектуры:

1. **CBOW (Continuous Bag-of-Words)** — предсказывает целевое слово по контексту (окружающим словам). Контекст усредняется, порядок слов не учитывается. Быстрее обучается, лучше для частых слов.

2. **Skip-gram** — обратная задача: по целевому слову предсказывает слова контекста. Работает медленнее, но лучше справляется с редкими словами и даёт более качественные векторы.

Обучение:
- Скрытый слой без нелинейности (по сути — линейное преобразование).
- Используется softmax над словарём, ускоренный через **negative sampling** или **hierarchical softmax**.
- Веса входного/выходного слоёв становятся эмбеддингами слов.

Свойства: векторы позволяют выполнять арифметику (king − man + woman ≈ queen), отражают семантическую и синтаксическую близость.

Ответ с RAG:

> Модель word2vec принимает большой текстовый корпус в качестве входных данных, строит из него словарь и далее из корпуса и словаря строит сопоставление: каждому слову из словаря сопоставляется вектор чисел с плавающей точкой (векторное представление слов), которое алгоритм выдаёт на выход. Векторное представление слов вычисляется для всех слов словаря с помощью алгоритма машинного обучения на входном тексте корпуса; целью машинного обучения является сопоставление контекстно близким словам близко расположенных векторов — слова, встречающиеся в тексте рядом с одинаковыми словами (и следовательно, имеющие сходный смысл), будут иметь близкие (по косинусной схожести) вектора [2].

Word2vec имеет два варианта моделирования слов контекста (построения предсказывающей модели слов контекста) [5]:
- CBoW (Continuous Bag of Words, «непрерывный мешок слов») — вариант word2vec, который предсказывает текущее центральное слово окна контекста, исходя из окружающих его слов в этом окне;
- Skip-gram (n-грамма с пропущенным центральным словом) — вариант word2vec, который, наоборот, предсказывает окружающие слова в окне контекста на основе текущего центрального слова окна.

При этом в алгоритме word2vec порядок слов контекста внутри окна не влияет на результирующий вектор представления [5].

RAG помогает устранить такие ограничения LLM, как устаревание информации, наличие неточностей или появление галлюцинаций [2].

### q3. Что такое косинусное сходство и как оно вычисляется для двух векторов?

**Ожидание:** Приведена формула косинуса угла между векторами (скалярное произведение, делённое на произведение норм), указан диапазон значений и отмечено, что метрика не зависит от длины векторов.
**Источники:** косинусное_сходство — статья Википедии

**Без RAG (2/2):** Ответ содержит формулу косинусного сходства через скалярное произведение и нормы векторов, указывает диапазон значений от -1 до 1 и явно отмечает независимость от длины векторов. Фактических ошибок нет.
**С RAG (1/2):** Ответ содержит формулу косинусного сходства (скалярное произведение, делённое на произведение норм), но отсутствуют указание диапазона значений и явное упоминание независимости от длины векторов. Также есть ссылки на контекст и коэффициент Отиаи, не требуемые ожиданием.

Ответ без RAG:

> **Косинусное сходство** — мера схожести двух векторов, равная косинусу угла между ними. Показывает, насколько векторы «смотрят» в одну сторону, игнорируя их длину.

**Формула:**
```
cos(θ) = (A · B) / (||A|| * ||B||)
```
где:
- `A · B` — скалярное произведение: Σ(aᵢ * bᵢ)
- `||A||` — длина вектора: √Σ(aᵢ²)

**Свойства:**
- Диапазон: от −1 до 1
- 1 — векторы сонаправлены
- 0 — ортогональны (не связаны)
- −1 — противоположны

**Пример:** A = (1, 2), B = (2, 4)
- A·B = 2 + 8 = 10
- ||A|| = √5 ≈ 2.236, ||B|| = √20 ≈ 4.472
- cos = 10 / (2.236 × 4.472) ≈ 1.0 → векторы коллинеарны

**Где применяется:** поиск похожих текстов, рекомендательные системы, эмбеддинги в ML.

Ответ с RAG:

> Согласно контексту, косинусное сходство (геометрический коэффициент) — это обобщение коэффициента Отиаи, используемое во множестве приложений как мера близости элементов произвольного нормированного пространства как отношение скалярного произведения к произведению норм [2].

Оно вычисляется по формуле:

cosim(A, B) = (A · B) / (‖A‖ ‖B‖) [2]

В евклидовом пространстве таким же образом определяется косинус угла между векторами A и B [2]. При рассмотрении произвольных множеств как битовых векторов коэффициент Отиаи совпадает с косинусным сходством [2].

### q4. Что такое инвертированный индекс и зачем он нужен в информационном поиске?

**Ожидание:** Объяснена структура: отображение «термин → список документов/позиций»; указано, что он ускоряет поиск документов по словам вместо полного перебора.

**С RAG (2/2):** Ответ полностью соответствует ожиданию: объяснена структура «термин → список документов/позиций» (включая вариант с позициями), указано, что индекс ускоряет поиск документов по словам (через прямое извлечение списков и пересечение для многословных запросов) вместо полного перебора. Ответ без RAG:

> **Инвертированный индекс** — это структура данных, которая отображает соответствие «термин → список документов (и позиций), где он встречается». В отличие от прямого индекса («документ → его слова»), она позволяет быстро находить документы по слову, а не перебирать все документы.

**Зачем нужен:**
- **Скорость поиска.** Вместо полного перебора корпуса (O(N) по документам) поиск сводится к выбору готового списка вхождений (posting list) для каждого терма запроса.
- **Быстрая булева логика.** AND/OR/NOT реализуются через пересечение/объединение/разность posting-списков.
- **Ранжирование.** Хранимые частоты и позиции позволяют считать TF-IDF, BM25, фразовый поиск, близость слов.
- **Масштабируемость.** Основа практически всех поисковых систем (Lucene, Elasticsearch, Sphinx).

Кратко: это «алфавитный указатель» по содержимому корпуса, превращающий поиск из перебора в быстрый доступ по ключу.

Ответ с RAG:

> Инвертированный индекс (англ. inverted index) — это структура данных, в которой для каждого слова коллекции документов в соответствующем списке перечислены все документы в коллекции, в которых оно встретилось. Инвертированный индекс используется для поиска по текстам [2].

Существует два варианта инвертированного индекса: индекс, содержащий только список документов для каждого слова, и индекс, дополнительно включающий позицию слова в каждом документе [2].

В информационном поиске инвертированный индекс применяется для решения задачи нахождения документов, в которых встречаются все слова из поискового запроса. При обработке однословного поискового запроса ответ уже есть в инвертированном индексе — достаточно взять список, соответствующий слову из запроса. При обработке многословного запроса берётся пересечение списков, соответствующих каждому из слов запроса. Обычно в поисковых системах после построения с помощью инвертированного индекса списка документов, содержащих слова из запроса, идёт ранжирование документов из списка. Инвертированный индекс — это самая популярная структура данных, которая используется в информационном поиске [4].

### q5. Как устроена архитектура трансформера и какую роль в ней играет механизм внимания?

**Ожидание:** Упомянуты self-attention/многоголовое внимание, encoder/decoder и позиционное кодирование; объяснено, что внимание взвешивает значимость токенов друг для друга.
**Источники:** трансформер_машинное_обучение — статья Википедии

**Без RAG (2/2):** Ответ полностью соответствует ожиданию: упомянуты self-attention/многоголовое внимание, encoder/decoder и позиционное кодирование; корректно объяснено, что внимание взвешивает значимость токенов друг для друга через Q/K/V и softmax. Фактических ошибок и выдумок нет.
**С RAG (1/2):** Ответ упоминает encoder/decoder, self-attention и позиционное кодирование, но не описывает многоголовое внимание и не объясняет, что внимание взвешивает значимость токенов друг для друга; вместо этого приведена формула и детали, не требуемые ожиданием.

Ответ без RAG:

> # Архитектура трансформера

**Основа:** стопка одинаковых блоков (энкодер + декодер в оригинале, либо только энкодер/декодер в вариантах типа BERT/GPT).

## Компоненты блока

1. **Multi-Head Self-Attention** — каждый токен «смотрит» на все остальные и собирает контекст.
2. **Feed-Forward Network (FFN)** — двухслойный MLP, применяется к каждому токену независимо.
3. **Residual connections + LayerNorm** — вокруг каждого подблока.
4. **Positional encoding** — добавляет информацию о порядке, т.к. внимание само по себе перестановочно-инвариантно.

## Механизм внимания

Для каждого токена строятся три вектора: **Query (Q)**, **Key (K)**, **Value (V)**.

```
Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V
```

- `QKᵀ` — скалярные произведения: насколько токен i «релевантен» токену j.
- `√d_k` — нормировка, чтобы градиенты не затухали.
- `softmax` — превращает в веса (сумма = 1).
- Умножение на `V` — взвешенная сумма значений.

**Multi-Head:** параллельно несколько таких «голов» с разными проекциями → модель улавливает разные типы связей (синтаксис, кореференцию, дальние зависимости).

## Роль внимания

- **Контекстуализация:** каждое представление токена обогащается информацией от всех остальных.
- **Динамические связи:** веса зависят от входа, а не фиксированы (в отличие от CNN/RNN).
- **Параллелизм:** в отличие от RNN, все позиции обрабатываются одновременно → эффективное обучение на GPU.
- **Гибкость охвата:** одна голова может ловить локальные связи, другая — дальние.

## Кратко

Трансформер = внимание (смешивает информацию между токенами) + FFN (обрабатывает её) + позиционные кодировки (порядок) + residual/LayerNorm (стабильность). Внимание — ядро, отвечающее за обмен контекстом.

Ответ с RAG:

> Архитектура трансформера состоит из кодировщика и декодировщика. Кодировщик получает на вход векторизованную последовательность с позиционной информацией. Декодировщик получает на вход часть этой последовательности и выход кодировщика. Кодировщик и декодировщик состоят из слоёв: слои кодировщика последовательно передают результат следующему слою в качестве его входа, а слои декодировщика последовательно передают результат следующему слою вместе с результатом кодировщика в качестве его входа. Каждый кодировщик состоит из механизма самовнимания (вход из предыдущего слоя) и нейронной сети с прямой связью (вход из механизма самовнимания). Каждый декодировщик состоит из механизма самовнимания (вход из предыдущего слоя), механизма внимания к результатам кодирования (вход из механизма самовнимания и кодировщика) и нейронной сети с прямой связью (вход из механизма внимания) [3].

Роль механизма внимания: механизм внимания параметризован матрицами весов запросов W_Q, весов ключей W_K, весов значений W_V. Эти вектора используются для вычисления результата внимания по формуле Attention(Q, K, V) = softmax(QK^T / √d_k) V [5]. Кроме того, механизм Self-Attention не имеет встроенного понимания позиций, поэтому для учёта порядка элементов в последовательности используется позиционное кодирование, добавляющее информацию о позиции каждого токена [2].

**С RAG (0/2):** Ответ не соответствует ожиданию: определение токенизации дано в контексте лексического анализа компиляторов, а не как разбиение текста на токены (слова, подслова, символы). Ответ без RAG:

> **Токенизация** — разбиение текста на элементарные единицы (токены): слова, подслова, символы. Нужна, чтобы превратить текст в последовательность чисел для модели.

**Основные подходы:**

1. **По словам** — простой, но большой словарь, проблема OOV (незнакомых слов) и редких форм.
2. **По символам** — маленький словарь, но длинные последовательности и потеря смысла.
3. **По подсловам (subword)** — компромисс, стандарт в современных LLM:
   - **BPE** (Byte Pair Encoding) — итеративно сливает частые пары символов (GPT, RoBERTa).
   - **WordPiece** — как BPE, но выбирает пару по вероятности (BERT).
   - **Unigram** — начинает с большого словаря и удаляет наименее полезные токены (T5, mBART).
   - **SentencePiece** — работает напрямую с сырым текстом, без предварительной сегментации по пробелам (подходит для языков без пробелов).
4. **Байтовый уровень** — токены = байты, нет OOV вообще (ByT5, GPT-2 частично).

На практике чаще всего используют BPE/SentencePiece с размером словаря 30k–100k токенов.

Ответ с RAG:

> Токенизация (лексический анализ, от англ. tokenizing) — это процесс аналитического разбора входной последовательности символов на распознанные группы — лексемы — с целью получения на выходе идентифицированных последовательностей, называемых «токенами» [1].

Лексический анализатор (токенизатор) — это программа или часть программы, выполняющая лексический анализ. Обычно он работает в две стадии: сканирование и оценка [2].

- На первой стадии, сканировании, лексический анализатор обычно реализуется в виде конечного автомата, определяемого регулярными выражениями. В нём кодируется информация о возможных последовательностях символов, которые могут встречаться в токенах. Например, токен «целое число» может содержать любую последовательность десятичных цифр. Во многих случаях первый непробельный символ может использоваться для определения типа следующего токена, после чего входные символы обрабатываются один за другим, пока не встретится символ, не входящий во множество допустимых символов для данного токена. В некоторых языках правила разбора лексем несколько более сложные и требуют возвратов назад по читаемой последовательности [2].
- Полученный таким образом токен содержит необработанный исходный текст (строку). Для того чтобы получить токен со значением, соответствующим типу (например, целое или дробное число), выполняется оценка этой строки — проход по символам и вычисление значения [2].

Токен с типом и соответственно подготовленным значением передаётся на вход синтаксического анализатора [2].

**С RAG (2/2):** Ответ содержит определение n-граммы как последовательности из n соседних элементов, упоминает униграмму (через общее определение), биграмму и триграмму, а также указывает применение в языковых моделях и предсказании следующего слова. Фактических ошибок нет.

Ответ без RAG:

> **N-граммы** — это последовательности из *n* смежных элементов (обычно слов или символов) в тексте.

Примеры для предложения «я люблю кофе»:
- 1-граммы (униграммы): «я», «люблю», «кофе»
- 2-граммы (биграммы): «я люблю», «люблю кофе»
- 3-граммы (триграммы): «я люблю кофе»

**Где применяются в NLP:**

1. **Языковое моделирование** — оценка вероятности следующего слова на основе предыдущих n−1 (классические n-граммные модели до появления нейросетей).
2. **Машинный перевод** — метрика BLEU сравнивает n-граммы перевода с эталоном.
3. **Автокоррекция и предиктивный ввод** — предсказание следующего слова.
4. **Классификация текста** — n-граммы как признаки (например, в наивном Байесе).
5. **Поиск и извлечение информации** — индексация фраз, определение коллокаций.
6. **Проверка орфографии** — оценка правдоподобности словосочетаний.

**Плюсы:** простота, интерпретируемость, работают без обучения.
**Минусы:** разреженность данных (чем больше n, тем реже встречаются комбинации), нет обобщения — не улавливают смысловую близость («автомобиль» и «машина» для них разные). Поэтому в современных задачах их часто заменяют эмбеддинги и трансформеры.

Ответ с RAG:

> N-грамма — это последовательность, состоящая из n элементов, которые могут быть звуками, слогами, словами или буквами, в зависимости от контекста. Чаще всего N-грамма — это последовательность слов, устойчивые сочетания которых называются словосочетаниями. Последовательность из двух элементов называется биграммой, а последовательность из трёх элементов называется триграммой. Последовательность, состоящая из четырёх или более элементов, называется N-граммой, где N — количество элементов [2].

В области обработки естественного языка N-граммы используются в основном для предугадывания на основе вероятностных моделей. N-граммная модель рассчитывает вероятность последнего слова N-граммы, если известны все предыдущие; при этом предполагается, что появление каждого слова зависит только от предыдущих слов [1].

N-граммы часто успешно используются для категоризации текста и языка. Кроме того, их можно использовать для создания функций, которые позволяют получать знания из текстовых данных. Они позволяют анализировать и описывать синтаксическую структуру языка и могут быть использованы в тех же областях, что и линейные N-граммы, включая применение в качестве элементов векторной модели [3].

**Источники:** natasha_README — README библиотеки

**Без RAG (2/2):** Ответ включает все ключевые возможности natasha: сегментация, токенизация, морфология/лемматизация, NER и извлечение фактов (включая нормализацию дат). Дополнительные пункты не противоречат ожиданию и не содержат фактических ошибок.
**С RAG (2/2):** Ответ включает все ключевые элементы ожидания: токенизацию, сегментацию, морфологию/лемматизацию, извлечение именованных сущностей (NER) и фактов. Дополнительные сведения не противоречат ожиданию и не содержат фактических ошибок.

Ответ без RAG:

> Библиотека Natasha предоставляет инструменты для обработки русского языка:

- **Сегментация на предложения** (`Segmenter`)
- **Токенизация** (`Tokenizer`)
- **Морфологический анализ** и лемматизация (`MorphVocab`, `NewsEmbedding`)
- **NER** — извлечение именованных сущностей: люди, локации, организации (`NerTagger`)
- **Извлечение фактов** — отношения между сущностями (`FactExtractor`)
- **Нормализация дат** (`NatashaDate`)
- **Разрешение местоимений** (`CoreferenceResolver`)
- **Определение адресов** (`AddressExtractor`)
- **Классификация новостей** по рубрикам (`NewsClassifier`)

Работает на предобученных моделях, поддерживает пайплайны и интеграцию с другими библиотеками (например, spaCy).

Ответ с RAG:

> Библиотека Natasha решает базовые задачи NLP для русского языка: токенизацию, сегментацию предложений, word embedding, морфологический разбор, лемматизацию, нормализацию фраз, синтаксический разбор, NER-разметку и извлечение фактов. Качество на каждой задаче сопоставимо или лучше текущих SOTA для русского языка на новостных статьях. Natasha не является исследовательским проектом — лежащие в её основе технологии созданы для продакшена; уделяется внимание размеру модели, использованию RAM и производительности. Модели работают на CPU и используют Numpy для инференса.

Natasha объединяет библиотеки проекта Natasha под одним удобным API:
- Razdel — токенизация и сегментация предложений для русского языка
- Navec — компактные русские эмбеддинги
- Slovnet — современные deep-learning-техники для русского NLP, компактные модели для русской морфологии, синтаксиса, NER
- Yargy — rule-based извлечение фактов, аналогичное Tomita parser
- Ipymarkup — визуализации NLP для NER и синтаксической разметки
