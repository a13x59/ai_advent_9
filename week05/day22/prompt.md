## Тестовый пример
Корпус: 19 документов (~168 тыс. символов после нормализации, ~90 страниц) —
статьи русской Википедии, README и исходный код. Модель эмбеддингов:
`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384 dim, cosine).

| Параметр | Fixed | Structural |
|---|---|---|
| Кол-во чанков | 265 | 396 |
| Средняя длина | 783 симв. | 422 симв. |
| Std длины | 201 симв. | 554 симв. |
| Recall@5 | 0.222 | 0.232 |
| MRR@10 | 0.810 | 0.827 |
| nDCG@10 | 0.509 | 0.481 |
| Время индексации | 3.32 с | 2.66 с |
| Размер индекса | 0.85 МБ (0.41 FAISS + 0.44 DB) | 1.02 МБ (0.61 FAISS + 0.41 DB) |
| Плюсы | равномерные чанки (низкая дисперсия), предсказуемый размер, чуть выше nDCG@10, простота | смысловые разделы, заполнен `section`, чуть выше Recall@5 и MRR@10, нет дублирования |
| Минусы | режет по произвольной границе (рвёт абзац/мысль), `section` пуст, overlap дублирует текст | сильная неравномерность (от 7 до 4202 симв.), зависит от качества заголовков, чуть ниже nDCG@10 |

## Детали

- **Fixed** (окно ~100 слов, перекрытие 20 слов) даёт 265 чанков средней
  длины 783 симв. с низкой дисперсией (std 201). Из-за перекрытия суммарный
  объём проиндексированного текста больше (207.6 тыс. симв. против 167.1 тыс.).
- **Structural** (заголовки markdown/вики + границы функций/классов, длинные
  секции дорезаются по абзацам) даёт 396 чанков; у 342+ из них заполнен
  `section`. Дисперсия длины высокая (std 554): встречаются и очень мелкие
  (7 симв.), и очень крупные (4202 симв.) чанки — длинный абзац не разрывается.
- **Метрики** близки: Recall@5 ≈ 0.22–0.23, MRR@10 ≈ 0.81–0.83. Structural
  чуть лучше по Recall@5 и MRR@10 (точнее попадает в нужный раздел), Fixed —
  чуть лучше по nDCG@10 (плотнее ранжирование релевантных чанков в топе).
  На маленьком тест-сете (14 запросов) эта разница в пределах шума.
- **Время и размер** сопоставимы: эмбеддинги доминируют в общем времени.
  Structural хранит больше векторов (396 против 265), поэтому FAISS-файл
  чуть больше.

## Ограничения оценки

- Релевантность задана на уровне документа (`source`/`title`), поэтому она
  одинакова для обеих стратегий — сравнение честное, но грубое.
- Короткие «заглушки» корпуса (статья «Лемматизация» — 665 симв.) и
  англоязычный README razdel плохо находятся обеими стратегиями: мультиязычная
  модель слабо связывает русский запрос с английским текстом.

## Вывод

Обе стратегии работоспособны и дают близкое качество поиска на данном корпусе.
Основное различие — **структура чанков, а не метрики**: structural даёт
смысловые чанки с заполненным `section` (удобно для навигации и метаданных),
fixed — равномерные чанки (удобно для батч-обработки и стабильного размера).
На практике их часто комбинируют: структурное разбиение + ограничение
максимальной длины чанка.
