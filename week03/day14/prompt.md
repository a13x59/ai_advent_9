## Ответ DeepSeek Harness:
Готово. Реализовал инварианты целиком: хранилище, детекцию конфликта, отказ, API и UI. Всё проверено end-to-end (в мок-режиме).

Что сделано
Хранилище (storage.py
)

Новая таблица invariants + CRUD, загрузка/персистенция по образцу профилей и задач.
Скоуп — три явных поля profile_id / session_id / task_id; пустое поле = «без привязки к этому измерению», все три пустые = глобальный.
get_applicable_invariants(profile_id, session_id, task_id) — применимые к запросу (активные + совпадение по всем заполненным измерениям).
Очистка сирот: при удалении профиля/задачи/сессии удаляются и привязанные инварианты.
Логика агента (main.py
)

build_invariants_system_block() — блок «ИНВАРИАНТЫ … НЕЛЬЗЯ нарушать» инжектится первым системным сообщением (не обрезается по importance).
check_invariants() — отдельный LLM-вызов-классификатор (temperature 0, строгий JSON-вердикт {violation, invariant_name, reason}); ключевых слов нет.
При violation=true — детерминированный отказ build_refusal_reply(), основная модель не вызывается, задача не создаётся и конечный автомат не двигается. В ответе /agent поля refused + violated_invariant (машинно-читаемо).
Endpoints: GET/POST /invariants, POST /invariants/{id}/toggle, DELETE /invariants/{id}; GET /agent/{session_id} теперь возвращает invariants.
UI (index.html
)

Кнопка «🛡 Инварианты» + модалка: список по категории/скоупу, форма (имя, категория, скоуп, формулировка, «почему нельзя», примеры нарушений), вкл/выкл, редактирование, удаление.
В чате отказ подсвечивается чипом «⛔ нарушен инвариант».
Важная деталь про детекцию
Реальная проверка — это отдельный LLM-вызов, как ты и выбрал. Поле deny_examples (примеры нарушений) нужно только для мок-режима, где LLM физически нет: это явные триггеры, которые человек задаёт самому инварианту, чтобы продемонстрировать отказ без API-ключа. В реальном режиме классификатор решает по тексту правила, а не по списку слов.

Проверено (end-to-end, мок)
глобальный инвариант «стек — только Python», запрос «перепиши на Go» → refused=true, объяснение с указанием правила и причины, задача не создана;
ненарушающий запрос проходит как обычно;
session-scoped инвариант срабатывает только в своей сессии;
task-scoped — только в своей задаче;
toggle/delete/list работают.

## Тестовый пример
Тестовый пример (в UI)
Открой «🛡 Инварианты», создай: категория стек, имя Стек только Python, формулировка Весь код пишется только на Python, примеры нарушений go, rust, node.
В чате напиши «перепиши это на Go» → ассистент откажет и объяснит, какой инвариант и почему нарушен.
Запуск как обычно: uvicorn main:app --host 0.0.0.0 --port 8000 (с реальным DEEPSEEK_API_KEY детекция пойдёт через LLM; без ключа — мок).
