## Ответ DeepSeek Harness:
Готово. Реализовал явные переходы состояний задачи с гвардами, перестроив проект по согласованной схеме. Все тесты зелёные (18 passed).

Что сделано
Ядро FSM — task_state.py

Добавлены гварды: DEFAULT_GUARDS = {"plan_approved": False, "validation_passed": False} и STAGE_GUARDS (вход в execution требует plan_approved, в done — validation_passed).
Вместо тихой коэрции — validate_and_apply(task, update, source), возвращающая явный вердикт (accepted/rejected + причина + allowed/blocked).
Порядок проверок: недопустимое состояние → перескок этапа → таблица переходов → гварды. Перескок (planning → done, execution → done) отклоняется.
allowed_next_stages() / blocked_next_stages() в каноническом порядке; render_task_block() показывает разрешённые переходы и состояние гвардов модели.
Гварды меняет только источник user/manual — модель не может сама «утвердить» план.
Хранилище — storage.py

Колонки guards (tasks) и accepted (task_transitions) + миграции ALTER TABLE для существующих БД.
record_rejected_transition() — журнал отклонённых попыток (accepted=0); list_task_transitions отдаёт accepted.
Общий пайплайн — agent_core.py
 (новый)

Интерфейс AgentProvider (complete / suggest_memory / check_invariants).
Вся логика /agent + все CRUD-эндпоинты в фабрике create_app(provider, store) — единый код для реального и мок-режима.
Режимы: task (маркер → валидация → при отказе re-prompt до 2 раз, плохой ответ в историю не пишется), approve (детерминированный переход по гварду, без вызова модели), chat, отказ по инварианту.
Новый эндпоинт GET /agent/{sid}/tasks/{tid}/transitions → {current_stage, guards, allowed, blocked}; POST .../transition на запрет возвращает 409 с причиной.
Реальный провайдер — main.py
 (переписан, без моков)

Только DeepSeekProvider + create_app(...). Никаких is_mock/_mock_*/детерминированного фолбэка.
Мок-провайдер — mock_agent.py
 (новый)

MockProvider с детерминированными заглушками (та же логика жизненного цикла), create_mock_app(db_path) для тестов.
UI — index.html
: в панели задачи добавлен индикатор гвардов (план ✓/✗ · валидация ✓/✗).

Тесты: test_task_state.py
 (юниты FSM) и test_agent_flow.py
 (интеграция на мок-приложении через TestClient), conftest.py
 изолирует БД.

Как проверялось
Copy
.venv/bin/python -m pytest -q   →   18 passed
Покрыты: попытка перейти в недопустимое состояние, реакция ассистента (re-prompt + отклонённый переход в журнале + плохой ответ не в истории), корректность после паузы, полный жизненный цикл «план → утверждение → выполнение → валидация → подтверждение → done».

Важные следствия (как договаривались)
main.py
 теперь требует реальный DEEPSEEK_API_KEY — без него вызов API упадёт (моки из main.py удалены полностью). Для демо/тестов без сети есть mock_agent.py
: uvicorn mock_agent:app --port 8001.
Утверждение плана и подтверждение валидации — действия пользователя через текст-подтверждение («да/ок/утверждаю/подтверждаю» и т.п.), когда задача в состоянии expected_action=confirm. Кнопку не добавляли.
Логика «проект → план → реализация → валидация → финал» теперь жёстко: planning → execution только после утверждения, validation → done только после подтверждения, перескоки блокируются.
