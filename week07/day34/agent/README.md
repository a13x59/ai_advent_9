# AI Agent — ассистент с памятью, FSM, MCP и RAG

Учебный агент на Python (FastAPI). Принимает сообщение, собирает контекст из нескольких источников и отвечает через
LLM-провайдера (DeepSeek в облаке или локальная модель Ollama, например `llama3.1`).

## Возможности

- **LLM-провайдеры** — облачный DeepSeek и локальный Ollama (`llama3.1`) за общим интерфейсом `AgentProvider` (см.
  `docs/architecture.md`).
- **Три слоя памяти** — сессионная (диалог), рабочая (текущая задача), постоянная (профиль/решения/знания). Явные
  операции `save/delete/move` и автопредложения от модели.
- **Профили пользователей** — стиль, формат, ограничения; активный профиль подключается к каждому запросу.
- **Конечный автомат (FSM)** задач — `planning → execution → validation → done`
  с гвардами `plan_approved` / `validation_passed`.
- **Инварианты** — жёсткие правила, которые агент не вправе нарушать; проверка запроса до генерации и отказ при
  нарушении.
- **MCP-инструменты** — нативный function calling: гадание (шар/книга), курсы валют, пайплайн (search → summarize →
  save_to_file), git (ветка/файлы/diff).
- **RAG** — ретрив чанков из базы знаний через отдельный HTTP-сервис.
- **Веб-страница** — `index.html` (SPA) для управления всеми функциями.
- **Команда `/help`** — ассистент разработчика отвечает на вопросы о структуре проекта, используя документацию (RAG) и
  контекст git-репозитория (MCP).
- **Ассистент поддержки (`/support`)** — отвечает на вопросы о продукте по FAQ/документации (RAG-корпус `support`),
  учитывает контекст тикета и покупателя (MCP `support-mcp`): создаёт тикет, выводит номер и ведёт диалог в его
  контексте; на офтопик отвечает «нет информации».
- **Файловый ассистент (`/files`)** — активно работает с файлами проекта через MCP `files-mcp`: читает
  (`read_file`), ищет по нескольким файлам (`search_files`), анализирует и создаёт/меняет файлы
  (`write_file`/`edit_file`). Dry-run по умолчанию: сначала diff, затем — `apply=true` для сохранения.
  Сценарии: поиск использования API, обновление документации, генерация README/ADR/changelog, проверка инвариантов.

## Структура проекта

```
agent/
├── agent_core.py      # единый пайплайн + фабрика create_app (все эндпоинты)
├── main.py            # точка входа: DeepSeekProvider + MCP + RAG
├── local_main.py      # точка входа: LocalOllamaProvider (llama3.1)
├── local_provider.py  # провайдер Ollama (native /api/chat + OpenAI-совместимый)
├── storage.py         # SQLite-хранилище: сессии, ветки, память, профили, задачи, инварианты
├── task_state.py      # конечный автомат (этапы, гварды, валидация переходов)
├── mcp_client.py      # синхронные MCP-клиенты (Streamable HTTP / JSON-RPC)
├── rag_client.py      # HTTP-клиент RAG-ретрива
├── mock_agent.py      # детерминированный MockProvider для тестов
├── index.html         # веб-интерфейс (SPA)
├── support.html       # интерфейс ассистента поддержки
├── files.html         # интерфейс файлового ассистента (День 34)
├── support_demo.py    # консольное демо поддержки
├── files_demo.py      # консольное демо файлового ассистента
├── config.js          # конфигурация фронтенда (хосты/модели)
├── requirements.txt
├── docs/              # документация проекта (подключена в RAG)
└── test_*.py          # тесты
```

## Запуск

Все команды запускаются из папки `agent/` (иначе `uvicorn` не найдёт модуль `main`):

```bash
cd agent

# облачный провайдер (DeepSeek), порт 8000
uvicorn main:app --host 0.0.0.0 --port 8000

# локальный провайдер (Ollama llama3.1), порт 8002
uvicorn local_main:app --host 0.0.0.0 --port 8002
```

Для `/help`, RAG и `/support` дополнительно нужны:

```bash
# RAG-ретрив (индексы документации + support). Корпус поддержки собирается так:
cd ../rag && python -m src.pipeline run --corpus support
uvicorn src.server:app --host 0.0.0.0 --port 8891

# git-MCP (ветка/файлы/diff), порт 8892
cd ../git-mcp && ./gradlew run

# support-mcp (тикеты/покупатели, SQLite), порт 8893
cd ../support-mcp && ./gradlew run
```

Для файлового ассистента `/files` дополнительно нужен `files-mcp` (порт 8894);
скоуп по умолчанию — родительский каталог сервиса (весь проект `day34`), при
необходимости переопределяется переменной `FILES_ROOT`:

```bash
cd ../files-mcp && ./gradlew run
```

Веб-интерфейс поддержки — `support.html`, файлового ассистента — `files.html`
(открываются отдельно; ссылки есть на главной странице `index.html`).
Демо в консоли — `python support_demo.py [BASE_URL]` и `python files_demo.py [BASE_URL]`.

## Основные эндпоинты

| Метод    | Путь                                   | Назначение                              |
|----------|----------------------------------------|-----------------------------------------|
| POST     | `/agent`                               | Обработка сообщения (полный пайплайн)   |
| POST     | `/support`                             | Ассистент поддержки (RAG FAQ + тикеты)  |
| POST     | `/files`                               | Файловый ассистент (files-mcp, diff/apply) |
| GET/POST | `/agent/{id}/memory`                   | Память сессии (чтение / явные операции) |
| GET      | `/memory/longterm`                     | Постоянная память                       |
| POST     | `/profiles`, `/profiles/{id}/activate` | Профили                                 |
| GET/POST | `/invariants`                          | Инварианты                              |
| GET/POST | `/agent/{id}/tasks`                    | Задачи (FSM)                            |
| GET      | `/healthz`, `/limits`                  | Статус и лимиты                         |

Подробно — в `docs/api.md`, схемы данных — в `docs/data-model.md`.
