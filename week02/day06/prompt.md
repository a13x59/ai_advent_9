🔥 День 6. Первый агент

Реализуйте простого агента, который:
👉 принимает запрос пользователя
👉 отправляет его в LLM через API
👉 получает ответ
👉 выводит результат в вашем интерфейсе

(простой чат, CLI или web, запросы через HTTP-клиент)

Важно:
👉 агент должен быть отдельной сущностью, а не просто один вызов API
👉 логика запроса и ответа должна быть инкапсулирована в агенте

Результат:
Агент принимает запрос и корректно вызывает LLM через API

Формат:
Видео + Код

Промпт:
контекст - необходимо подготовить веб сервис - ИИ агента, который
- принимает запрос пользователя
- отправляет его в LLM через API
- получает ответ
- выводит результат в интерфейсе

приложение состоит из 2х частей:
1. сервер
напиши бэкенд для обращения в апи deepseek (используй следующую заглушку для параметра API_KEY = "sk-123567890")
использую python в качестве стека. каждому запросу присваивается уникальный идентификатор (UUID) - по сути id агента.
данный сервис должен принимать запросы в формате http (REST), на выходе в ответе json который вернула llm в разрезе каждого агента.
на входе у сервиса также параметры апи deepseek (массив параметров агента), включая, но не ограничиваясь - сообщение (обязательное), название модели (обязательное), температура, top_k, top_p, стоп последовательность, максимальное кол-во токенов.
если опциональный параметр не передан - используется значение по умолчанию.

2. клиент
представляет собой веб страницу. на странице есть поля ввода агента, описанные ранее - включая, но не ограничиваясь - сообщение (обязательное), название модели (обязательное), температура, top_k, top_p, стоп последовательность, максимальное кол-во токенов.
клиент хранит на своей стороне историю сообщений и отправляет ее в каждом запросе.
в поле ответа необходимо вывести статистику - сколько времени заняла обработка, сколько токенов потрачено, примерная стоимость.
используй современное оформление, стили актуальные на 2026 год.
клиент использует адрес апи сервера.
