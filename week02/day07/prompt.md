## Ответ DeepSeek Harness:
Готово. Я расширил агента сохранением/восстановлением контекста между сессиями, не трогая остальную логику (запросы к DeepSeek, мок-заглушку, расчёт статистики и оформление страницы).

Что изменилось
Новый файл storage.py — слой хранения истории в SQLite (файл agent_history.db создаётся автоматически рядом с сервером):

HistoryStorage сохраняет messages по session_id, умеет загружать/сохранять/удалять сессии.
При старте вызывается load_all_history() — история из БД загружается обратно в память (это и есть «загрузка истории при перезапуске агента»).
Изменён main.py:

В модель запроса добавлен необязательный session_id.
POST /agent теперь: восстанавливает сохранённый контекст по session_id (или создаёт новую сессию), добавляет новое сообщение пользователя, вызывает модель, дописывает ответ ассистента и сохраняет всё в БД. В ответе возвращается session_id.
Добавлены эндпоинты: GET /agent/{session_id} (вернуть историю), GET /agents (список сессий), DELETE /agent/{session_id} (сброс).
Изменён index.html:

session_id хранится в localStorage и отправляется в каждом запросе.
При загрузке страницы история восстанавливается с сервера, поэтому диалог продолжается как после перезапуска агента, так и после перезагрузки браузера.
Добавлена кнопка «↺ Новый диалог» для сброса контекста.
Проверка
Я прогнал end-to-end смоук-тест (установил стек во временный venv, затем удалил его): диалог накапливается, после реального перезапуска uvicorn история восстанавливается из SQLite, продолжение идёт корректно, удаление сессии отдаёт 404. Все проверки прошли (ALL TESTS PASSED).

Запуск без изменений: uvicorn main:app --host 0.0.0.0 --port 8000. Путь к БД можно переопределить переменной окружения AGENT_HISTORY_DB.
